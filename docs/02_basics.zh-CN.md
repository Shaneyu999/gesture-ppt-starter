# 基础知识参考

这篇文档帮助没有深度学习基础的读者理解手势识别和实时控制项目。

## 1. 图像分类是什么

图像分类输入一张图片，输出一个类别：

```text
图片 -> 模型 -> palm / peace / thumbs_up / fist
```

模型会把图片转换为数字，再计算它属于各个类别的概率。

## 2. 摄像头视频帧

视频可以看成按时间排列的图片：

```text
第1帧 -> 第2帧 -> 第3帧 -> ...
```

OpenCV 使用 `VideoCapture` 读取摄像头，每一帧通常是 BGR 顺序的 NumPy 数组。

本项目只取画面中央区域进行分类，因为手通常放在中央，也可以减少背景干扰。

## 3. 为什么先裁剪中央区域

如果直接对整张画面分类，模型可能学习到：

- 桌子；
- 墙面；
- 人体；
- 显示器；
- 固定光照。

中央裁剪让手占据更大比例，可以提高稳定性。参数 `--roi 0.65` 表示取画面短边的 65%。

## 4. 张量

PyTorch 图像分类常见输入形状：

```text
[N, C, H, W]
```

- N：batch size；
- C：RGB 通道数，通常为 3；
- H：高度；
- W：宽度。

模型实际输入通常是 224 × 224。

## 5. 训练集和验证集

- 训练集：更新模型参数；
- 验证集：选择最佳模型；
- 测试集：最终只评估一次。

手势数据的主要风险是数据泄漏。如果训练集和验证集来自同一段连续录像，相邻帧几乎相同，验证准确率会虚高。

正确做法是使用不同 session、背景或人员。

## 6. 数据增强

常见增强：

- 随机裁剪；
- 随机水平翻转；
- 亮度变化；
- 对比度变化；
- 饱和度变化；
- 轻微色相变化。

增强可以模拟不同环境和手的位置。但水平翻转可能让某些方向性手势改变含义，需要根据手势定义决定是否使用。

## 7. 迁移学习

从零训练一个图像模型需要大量数据。迁移学习先使用 ImageNet 预训练模型，再改成自己的类别。

本项目：

1. 加载 MobileNetV3-Small；
2. 保留前面的特征提取层；
3. 把最后的分类层改成四类；
4. 用少量手势图片训练。

如果数据很少，可先冻结主干，只训练最后分类层：

```powershell
--freeze-backbone
```

数据增加后，可以解冻模型做完整微调。

## 8. MobileNetV3 是什么

MobileNetV3 是面向移动和边缘设备设计的轻量卷积网络。

优点：

- 参数量少；
- 推理速度快；
- 对 CPU 较友好；
- 适合实时 Demo。

缺点：

- 表达能力比大型模型弱；
- 面对复杂背景时可能不稳定；
- 需要高质量训练数据。

## 9. 分类输出和概率

模型输出 logits，经过 Softmax 后得到每个类别的概率：

```text
palm       0.08
peace      0.91
thumbs_up  0.01
fist       0.00
```

默认取概率最大的类别。置信度阈值用于过滤低质量预测。

## 10. 为什么不能每一帧都按键

实时视频每秒可以处理几十帧。假设模型在 1 秒内连续识别出 20 次剪刀手，如果每帧都发送 `right`，幻灯片会连续翻很多页。

因此需要：

### 连续帧

同一手势连续出现 5 帧才触发。

### 冷却时间

同一个动作执行后，1.5 秒内不再重复执行。

### 置信度

低于 0.60 的预测不参与触发。

## 11. 状态机思路

本项目使用简化状态机：

```text
当前没有候选手势
  -> 连续看到 peace
  -> 计数增加
  -> 达到稳定帧数
  -> 检查冷却时间
  -> 触发 next
  -> 重置计数
```

如果识别结果切换，候选手势会重新开始计数。

## 12. 键盘控制

`pyautogui.press()` 可以把按键发送给当前前台窗口。

例如：

```python
pyautogui.press("right")
```

这意味着：

- PPT 必须在最前面；
- 如果焦点在摄像头窗口，按键可能不会进入 PPT；
- 不要在没有监督时控制重要软件；
- 默认预览模式更安全。

## 13. 为什么使用键盘而不是 PowerPoint API

键盘控制：

- 对 PPT、视频播放器和浏览器都通用；
- 实现简单；
- 不需要安装 Office 插件；
- 适合快速 Demo。

限制：

- 依赖当前前台窗口；
- 按键映射可能因软件不同而不同；
- 无法读取 PPT 当前页码或播放状态。

## 14. 模型保存

训练后保存：

```text
runs/gesture_model/best.pt
```

检查点中包含：

- 模型参数；
- 类别顺序；
- 输入图像尺寸；
- 最佳验证指标。

推理时必须保持类别顺序一致，因此加载模型时直接读取检查点中的标签。

## 15. 评价指标

### Accuracy

预测正确比例。

### Macro F1

每个类别 F1 的平均值，适合判断少数手势是否被忽略。

### 每类召回率

某手势中被正确识别的比例。

### 混淆矩阵

观察哪些手势容易混淆，例如：

- 剪刀手与手掌；
- 握拳与点赞；
- 手掌与背景。

### FPS

每秒处理帧数。实时 Demo 的目标通常是 15 FPS 以上。

## 16. 常见数据问题

- 背景太固定；
- 同一 session 造成数据泄漏；
- 手势类别不平衡；
- 手离摄像头太远；
- 图片模糊；
- 某些手势连续帧几乎相同；
- 训练数据没有覆盖左手和右手。

## 17. 常见训练问题

### 验证准确率一直不提高

- 增加数据；
- 先冻结主干；
- 检查标签是否放错；
- 调整学习率；
- 检查类别是否平衡。

### 训练准确率很高、验证很低

- 数据泄漏风险；
- 背景过拟合；
- 数据太少；
- 增强不足；
- 验证集分布与训练集不同。

### 实时预测不稳定

- 提高稳定帧数；
- 增加困难样本；
- 调整 ROI；
- 改善光照；
- 不要只看单帧结果。

## 18. 项目代码阅读顺序

1. `config.py`：标签和动作配置；
2. `data.py`：按文件夹读取图片；
3. `model.py`：MobileNetV3 和图像变换；
4. `train.py`：训练循环；
5. `predictor.py`：单图与摄像头推理；
6. `stability.py`：稳定帧与冷却时间；
7. `actions.py`：动作映射和键盘控制；
8. `camera.py`：采集和实时窗口；
9. `cli.py`：所有命令入口。
